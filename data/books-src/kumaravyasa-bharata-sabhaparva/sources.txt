# NOTE: the committed chapter files are HAND-EDITED after generation, AND re-running the bootstrap
# command above will NOT reproduce them byte-for-byte, because two behaviours of the shared
# fetch-wikisource.ts / lib/wikisource.ts pipeline actively mis-handle this particular source:
#
#   1. ಸಭಾಪರ್ವ sandhis 2 and 3 (not sandhi 1) mistype anusvara as the Kannada digit ೦ throughout
#      the page ("ಮ೦ತ್ರಿಗಳ" for "ಮಂತ್ರಿಗಳ", 396 occurrences in sandhi 2 and 234 in sandhi 3). Since
#      numbered mode's joinNumberedVerses() treats a line ending in any Kannada digit as a verse
#      end, this glitch made it flush a new "verse" in the middle of real verses constantly —
#      running --sources as-is produces 156 and 83 blocks for sandhis 2/3 instead of the true 129
#      and 67, most of them 1-2-4-5 line fragments. This was NOT hand-retyped: a one-off script
#      (not committed) re-derived the chapters from the same raw wikitext, calling the library's
#      own cleanWikitext(), but replacing every ೦ that is glued directly onto a non-digit
#      character (i.e. not part of a genuine multi-digit numeral like ೧೦/೨೦) with ಂ before
#      re-joining verses on a "digit run preceded by whitespace" rule instead of "line ends in a
#      digit". This is a mechanical, reviewable substitution, not free retyping.
#   2. lib/wikisource.ts's dropNonVerse() drops any line *starting with* ಅರ್ಥ/ತಾತ್ಪರ್ಯ/ಪದವಿಭಾಗ/
#      ವಿವರಣೆ even with no following colon, meant to strip modern ಅರ್ಥ: glosses. This page has no
#      such commentary, but it silently ate two genuine verse padas in sandhi 1 verse 28 that
#      happen to start with the word ಅರ್ಥ ("ಅರ್ಥದಿಂ ಧರ್ಮವನು ಧರ್ಮದಿ" / "ಅರ್ಥಸಾಧನ ಧರ್ಮಸಾಧನ", confirmed
#      against the raw wikitext) — the same one-off script restored them by only dropping such
#      lines when followed by a colon.
#
